# Adding a project repository

For each project, gather the source code or repository URL, project goal, your specific contribution, dependencies, run instructions, screenshots or a demo, and any results you can substantiate.

A useful repository usually includes:

- A README explaining the problem, solution, setup, and a reproducible example.
- Source files organized for the project's language or robotics framework.
- A dependency manifest and configuration example without secrets.
- Appropriate checks for the code and instructions for running them.
- A `.gitignore` for generated outputs, local environments, and credentials.
- A license selected according to ownership and any collaboration requirements.
- Screenshots, diagrams, or links to demonstrations.

Review code and assets for permission to publish, particularly work completed for an employer or a team. Add the confirmed URL as `repository` in the matching `_projects/` file when ready. Keep private implementation details out of public project pages.
